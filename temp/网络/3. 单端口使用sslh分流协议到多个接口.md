## **📚 整合指南：通过单一端口（51443）访问 HTTPS、SSH 及 NPC 服务**

---

1. 我有内网主机（**机器A**），**外网端口 51443 映射到机器A的 51443**。需实现以下目标：
- **外网仅通过 51443 端口访问内网服务**：
  - HTTPS 网站（A 的 443 端口）
  - SSH 远程连接（A 的 22 端口）
  - NPC 穿透服务(基于TCP)（A 的 8024 端口）
- **不干扰现有 1Panel + OpenResty 的 Web 服务管理**。

---
### **🌐 当前网络架构**
| 服务       | 内网端口 | 外网映射（网关） |
| -------- | ---- | -------- |
| HTTPS 网站 | 443  | 无        |
| SSH 服务   | 22   | 无        |
| NPC 服务端  | 8024 | 无        |

---

### **🚀 最终目标架构**
通过协议分流工具 `sslh`，将外网 51443 端口的流量智能分发到不同服务：
```
外网用户
│
├─ SSH 连接 → 外网:51443 → sslh → SSH:22
│
├─ HTTP 访问 → 外网:51443 → sslh → OpenResty:80
│
├─ HTTPS 访问 → 外网:51443 → sslh → OpenResty:443
│
├─ NPC 穿透 → 外网:51443 → sslh → TCP : 8024
│
└─ 其他流量 -> 443
```

---

### **🔧 操作步骤**

#### **1. 调整网关映射**
修改外网端口映射规则：
- **规则**：`外网 51443 → 内网 A:51443`
#### **2. 安装协议分流工具 `sslh`**
1. 使用apt进行安装（debian/Ubuntu）在机器A上安装 `sslh`，用于监听 51443 端口并分流流量：
```bash
sudo apt update
sudo apt install sslh
```
2. 从源码编译，一共有三个版本sslh-fork,sslh-select,sslh-ev,默认使用的是sslh-fork，sslh-ev性能最好
3. 下载仓库： https://github.com/yrutschle/sslh
	1. 运行 ./configure 进行生成Makefile包括config.h
	2. 运行make进行构建,需要安装libev,libconfig等库
	3. 在运行的机器上也要安装libev的库（如果使用ev版本）
	4. 然后将编译好的放在适当的位置，并重命名替代原程序
4. 如果有其他协议的分流需求需要先抓包，例如npc
	1. 在Linux上使用tcpdump抓包，或者使用win用wireshark抓包
		```bash
		sudo tcpdump -i lo "tcp port 51443" -w cap.pcap 
		```
	2. 在win上打开cap.pcap进行分析
#### **3. 配置 `sslh`**
1. 使用命令的形式，编辑配置文件 `sudo vim /etc/default/sslh`：
	1. 编辑配置文件
		```ini
		RUN=yes
		DAEMON_OPTS="--user sslh \
		        --listen 0.0.0.0:51443 \
		        --http 127.0.0.1:80 \  	       # HTTP 流量 -> OpenResty     
				--tls 127.0.0.1:443 \          # HTTPS 流量 → OpenResty
		        --ssh 127.0.0.1:22 \           # SSH 流量 → 本机 SSH
		        --anyprot 127.0.0.1:8024 \     # 其他流量 TCP
			--pidfile /var/run/sslh/sslh.pid"
		```
	2. 实际配置文件类似
		```ini
		# Default options for sslh initscript
		# sourced by /etc/init.d/sslh
		
		# binary to use: forked (sslh) or single-thread (sslh-select) version
		# systemd users: don't forget to modify /lib/systemd/system/sslh.service
		DAEMON=/usr/sbin/sslh
		RUN=yes
		DAEMON_OPTS="--user sslh  --listen 0.0.0.0:51443 --http 127.0.0.1:80 --tls 127.0.0.1:443 --ssh 127.0.0.1:22 --anyprot 127.0.0.1:8024  --pidfile /var/run/sslh/sslh.pid"
		```
2. 可以使用配置文件的方式，支持更多的规则包括使用正则表达式 `regex` 来匹配流量,创建配置文件到`/etc/sslh/sslh.cfg`，并且注意修改之前的配置文件 `sudo vim /etc/default/sslh`:
	1. 修改源配置文件 /etc/default/sslh
		```cfg
		# Default options for sslh initscript
		# sourced by /etc/init.d/sslh
		
		# binary to use: forked (sslh) or single-thread (sslh-select) version
		# systemd users: don't forget to modify /lib/systemd/system/sslh.service
		DAEMON=/usr/sbin/sslh
		RUN=yes
		DAEMON_OPTS="--config /etc/sslh/sslh.cfg"
		```
	2. 编辑基本配置文件  /etc/sslh/sslh.cfg
		```config
		# 这是一个基本的配置文件，适用于“标准”设置，提供了合理的默认值。
		# 更详细的示例和说明请参见 example.cfg
		
		# foreground: 是否以前台模式运行，true 便于调试，false 则转为后台守护进程
		foreground: false;
		timeout: 5;
		user: "nobody";
		pidfile: "/var/run/sslh.pid";
		
		# 日志配置
		# 取值：1：标准输出；2：syslog；3：标准输出+syslog；4：日志文件；...；7：全部
		# 这里标明了默认值，通常应合理。一般建议始终启用 *-error，以便发现问题。
		verbose-config: 0; # 启动时打印配置信息
		verbose-config-error: 3;  # 打印配置错误
		verbose-connections: 3; # 跟踪已建立的连接，从入站地址到转发地址
		
		# 指定日志文件路径
		logfile: "/var/log/sslh.log"
		
		# 指定使用哪个 syslog facility（系统通常在 /usr/include/*/sys/syslog.h 或类似文件中定义）
		# 默认是 "auth"
		# "none" 表示禁用 syslog
		syslog_facility: "auth";
		
		# 将主机名更改为您的外部地址名称，或接收连接的接口的 IP。
		# 默认情况下绑定所有接口。可以先启动 httpd 绑定到 localhost，
		# 这样 sslh 只会绑定到其他接口。
		listen:
		(
			# 注意最后一个没有','逗号
		    { host: "0.0.0.0"; port: "51443"; }
		);
		
		
		# 更改为您想要转发的协议。
		# 这里的默认值适用于在本地主机上运行的服务。
		protocols:
		(
		    { name: "ssh"; service: "ssh"; host: "127.0.0.1"; port: "22"; keepalive: true; },
		    { name: "http"; host: "127.0.0.1"; port: "80" },
		    # 匹配 NPC TLS 链接
		    { name: "tls"; sni_hostnames: [ "host.name" ]; host: "127.0.0.1"; port: "8080" },
		    # 其余的tls由nginx接管
		    { name: "tls"; host: "127.0.0.1"; port: "443";  tfo_ok: true},
		    # 匹配 NPC 链接
		    { name: "regex"; host: "127.0.0.1"; port: "8024"; regex_patterns: [ "^TST" ]; },
		    # 匹配 RDP
		    { name: "msrdp"; host: "127.0.0.1"; port: "3389"; },
		    # 剩余未匹配端口
		    { name: "anyprot"; host: "127.0.0.1"; port: "443"; },
		    # 超时后连接的目标（默认 ssh）
		    { name: "timeout"; service: "daytime"; host: "127.0.0.1"; port: "443" }
			# 注意最后的花括号后面没有 ','
		);
		```
重启服务：
```bash
sudo systemctl restart sslh
```

#### **4. 配置 NPC 服务端**
在机器A上启动 NPS 服务端，并按照教程配置创建好对应的客户端连接接口
#### **5. 配置 NPC 客户端**
在内网其他机器上运行 NPC 客户端，连接到 `remote_ip:8024`（由 `sslh` 分流）：
```bash
./npc -server="remote_ip:8025" -vkey=your_vkey -type=tcp -tls_enable
```
- **参数**：`-tls_enable` 强制加密,可选。启用后是链接到 8025端口，默认是8024（未启用tls链接）
#### **6. 保持 OpenResty 配置不变**
 OpenResty 仍监听 `443` 端口，无需修改。

### **🔍 故障排查**

#### **1. HTTPS 无法访问**
- **检查 OpenResty 是否运行**：
- **检查 `sslh` 转发日志**：
  ```bash
  sudo tcpdump -i any port 443 -nn
  ```

#### **2. SSH 连接失败**
- **检查 SSH 服务状态**：
  ```bash
  sudo systemctl status ssh
  ```
- **检查 `sslh` 分流规则**：
  ```bash
  sudo journalctl -u sslh -f | grep "ssh"
  ```

#### **3. NPC 连接超时**
- **检查 NPC 服务端端口**：
  ```bash
  sudo netstat -tuln | grep 8024
  ```
- **检查 NPC 客户端日志**：
  ```bash
  ./npc -server="your-domain.com:51443" -vkey=your_vkey -type=tcp -tls -log=debug
  ```
