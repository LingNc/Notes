1. 接上文的问题：
	2.有内网主机（**机器A**），**外网端口 51443 映射到机器A的 51443**。
	需实现以下目标：
	- **外网仅通过 51443 端口访问内网服务**：
	  - HTTPS/HTTP 网站（443）
	  - SSH（22）
	  - NPC（8024）
	  - socks代理 
2. 当前网络结构：
	1. 网关只开放一个51443端口，为了安全起见将所有的服务都共用同一个端口进行
	2. 网关的51443端口映射到本地的51443端口，然后通过分流51443端口上的流量来进行分流
3. 目标架构
	通过协议分流工具 HAPorxy，将外网 51443 端口的流量智能分发到不同服务：
	```
	外网用户
	│
	51443端口
	│
	HAProxy进行协议识别
	│
	├─ HTTPS 访问 → OpenResty:443
	│
	├─ HTTP 访问 -> OpenResty:80 
	│
	├─ SSH 连接 → SSH:22
	│
	├─ NPC 连接 -> NPS: 8024
	│
	└─ 其他TCP连接 = 直接丢弃
	```
4. 操作
	1. 抓包 NPC 的协议特征
		1. 使用 socat 获取 绑定到要链接的一个端口(8028)上
		```bash
		socat -v -x TCP-LISTEN:8028,fork,reuseaddr SYSTEM:'cat' 2>&1 | grep --line-buffered -v ">"
		```
		2. 使用 nc 获取流量原始数据
		```bash
		nc -l -p 8028 > npc_raw.bin
		```
		3. 抓取NPC的流量特征 16进制 的请求： 
		```hex
		54 53 54 06 00 00 00 30 2e 32 36 2e 30 07 00 00 00 30 2e 32 36 2e 32 32
		```
	2. 编辑配置文件:
	```cfg
	# 全局配置段 - 控制HAProxy进程级别的参数
	global
	    # 定义日志输出：使用本地syslog的local0设备记录日志
	    log /dev/log local0
	    # 设置最大连接数为100000
	    maxconn 100000
	    # 设置默认的DH参数长度（TLS安全优化）
	    tune.ssl.default-dh-param 2048
	    # 高级选项
	    # 增加缓冲区以处理大流量
	    tune.bufsize 16400
	    tune.maxrewrite 1024
	    nbthread 2  # 根据CPU核心数调整
	
	# 默认参数段 - 为所有frontend/backend提供默认值
	defaults
	    # 工作在TCP模式（四层负载均衡）
	    mode tcp
	    # 连接超时时间5秒
	    timeout connect 5s
	    # 客户端空闲超时30秒
	    timeout client 1h
	    # 服务端空闲超时30秒
	    timeout server 1h
	    # 继承全局日志配置
	    log global
	    # 启用TCP日志记录
	    option tcplog
	
	# 前端配置段 - 定义对外服务的监听端口和流量分发规则
	frontend unified_port
	    # 监听51443端口（IPv4和IPv6）
	    bind :51443
	    # 设置协议检测的最大等待时间为5秒
	    tcp-request inspect-delay 3s
	
	    # 1. 优先识别 HTTPS (基于TLS协议特征)
	    acl is_https req.ssl_hello_type 1
	    use_backend https_backend if is_https
	
	    # 2. 精准识别 SSH (完整握手协议头)
	    acl is_ssh payload(0,7) -m str SSH-2.0
	    use_backend ssh_backend if is_ssh
	
	    # 3. 识别 HTTP (匹配完整请求行)
	    acl is_http payload(0,3) -m sub "HTTP"
	    use_backend http_backend if is_http
	
	    # 4. 识别 NPC (魔数头 + 长度校验)
	    acl is_npc_head payload(0,3) -m sub "TST"
	    use_backend npc_backend if is_npc_head is_npc_flag
	
	    # 5. 识别 SOCKS5 (协议头 + 方法校验)
	    acl is_socks5_ver payload(0,1) -m bin 05    # VER=5
	    # NMETHODS 可选校验，通常首字节足够
	    use_backend socks5_backend if is_socks5_ver
	
	    # 6. 其他流量记录并丢弃
	    # log-format "%ci:%cp [%t] %ft %b/%s : %[payload(0,16)]"
	    default_backend trash_backend
	
	# 后端服务定义 - HTTPS服务
	backend https_backend
	    # 定义后端服务器：OpenResty的443端口
	    server openresty_https 127.0.0.1:443
	
	# 后端服务定义 - HTTP服务
	backend http_backend
	    # 定义后端服务器：OpenResty的80端口
	    server openresty_http 127.0.0.1:80
	
	# 后端服务定义 - SSH服务
	backend ssh_backend
	    # 定义后端服务器：SSH服务的22端口
	    server ssh_server 127.0.0.1:22
	
	# 后端服务定义 - NPC服务
	backend npc_backend
	    # 定义后端服务器：NPS服务的8024端口
	    server nps_server 127.0.0.1:8024
	
	# 后端服务定义 - SOCKS5代理
	backend socks5_backend
	    # 定义后端服务器：SOCKS代理的1080端口
	    server socks_proxy 127.0.0.1:1080
	
	# 后端服务定义 - 垃圾流量处理
	backend trash_backend
	    # 直接拒绝连接（返回TCP RST包）
	    mode tcp
	    tcp-response content reject
	    # error-log-format "Unknown protocol: %[payload(0,16)]"

	```

### 二、关键配置说明
#### 1. **协议识别优先级**
```yaml
优先级顺序：HTTPS > HTTP > SSH > NPC > SOCKS5 > 其他
```
- **HTTPS优先于HTTP**：因为所有HTTPS流量也包含类似GET/POST的明文，需优先匹配TLS握手特征
#### 2. **精准协议特征**
| 协议     | 检测方法               | 匹配内容示例                |
| ------ | ------------------ | --------------------- |
| HTTPS  | TLS Client Hello 包 | `0x16 0x03 0x01...`   |
| HTTP   | 首行包含 `GET`/`POST`  | `GET / HTTP/1.1`      |
| SSH    | 首包以 `SSH-` 开头      | `SSH-2.0-OpenSSH_8.2` |
| NPC    | 前4字节为 `54 53 54`   | `TST...`              |
| SOCKS5 | 首字节为 `0x05`        | `05 01 00`            |
### 三、部署步骤
1. **安装 HAProxy**
   ```bash
   apt-get install haproxy  # Debian/Ubuntu
   ```

2. **备份原配置**
   ```bash
   cp /etc/haproxy/haproxy.cfg /etc/haproxy/haproxy.cfg.bak
   ```

3. **应用新配置**
   ```bash
   vim /etc/haproxy/haproxy.cfg  # 粘贴上述配置
   systemctl restart haproxy
   ```
4. 检测配置是否填写正确
	sudo haproxy -c -f /etc/haproxy/haproxy.cfg
	输出： 
	Configuration file is valid
	
5. **验证服务状态**
   ```bash
   systemctl status haproxy
   ss -tulnp | grep 51443  # 确认端口监听
   ```

### 四、验证分流功能
#### 1. **测试 HTTPS 分流**
```bash
curl -k https://外网IP:51443  # 应看到OpenResty的443端口响应
```

#### 2. **测试 NPC 分流**
```bash
# 发送NPC握手包
echo -ne '\x54\x53\x54\x06\x00\x00\x00\x30' | nc 外网IP 51443
# 检查NPS服务日志是否收到连接
tail -f /var/log/nps.log
```

#### 3. **测试未知协议丢弃**
```bash
dd if=/dev/urandom bs=16 count=1 | nc 外网IP 51443

```

### 五、高级调优建议
1. **启用日志分析**
   ```bash
   # 配置rsyslog分离HAProxy日志
   echo "local0.* /var/log/haproxy.log" > /etc/rsyslog.d/99-haproxy.conf
   systemctl restart rsyslog
   ```

2. **动态配置重载**
   ```bash
   # 修改配置后无需重启
   haproxy -f /etc/haproxy/haproxy.cfg -c  # 检查配置
   systemctl reload haproxy
   ```

3. **防火墙加固**
   ```bash
   ufw allow 51443/tcp  # 仅开放必要端口
   ufw enable
   ```

4. 单独配置超时时间
	 backend ssh_backend
    timeout server 24h  # SSH连接保持24小时
    server ssh 127.0.0.1:22
5. 缺点并不能精确的识别协议，比较复杂调整
