**这是一个非常极客但也非常实用的需求！
4. 你想让这台机器用起来完全像一台普通的 Windows 电脑：按机箱上的电源键，Windows 关机；再按一下，Windows 开机。

**结论：** 物理电源键（Power Button）是连接在主板上的，属于 ACPI 硬件事件，**不能像 USB 那样直接“直通”**。但是，我们可以通过**“劫持”**的方法来实现这个效果。

**原理：**

1. **屏蔽 PVE 的默认行为：** 告诉 PVE 系统，“收到电源键按下信号时，不要自己关机”。
    
2. **编写“劫持”脚本：** 告诉 PVE，“收到信号后，去检查 Win10 的状态。如果它开着，就发命令让它关机；如果它关着，就发命令让它开机”。
    

---

### 操作步骤（请严格按照顺序执行）

#### 第一步：禁止 PVE 宿主机抢答（屏蔽宿主机关机）

默认情况下，按电源键 PVE 会立马执行宿主机原本的关机流程。我们需要把它关掉。

1. 在 PVE Shell 中，编辑 `logind.conf` 文件：
    
    Bash
    
    ```
    nano /etc/systemd/logind.conf
    ```
    
2. 找到 `HandlePowerKey` 这一行（前面可能有 `#` 注释）。把它修改为：
    
    Ini, TOML
    
    ```
    HandlePowerKey=ignore
    ```
    
    _（意思是：忽略电源键动作）_
    
3. 保存退出 (`Ctrl+O`, `Ctrl+X`)。
    
4. 立刻应用更改：
    
    Bash
    
    ```
    systemctl restart systemd-logind
    ```
    
    _此时，你按一下机箱电源键，你会发现 PVE **没有任何反应**了。这就对了！_
    

---

### 第二步：安装 ACPI 事件监听服务

我们需要一个“管家”来专门监听这个被忽略的按钮事件。

1. 安装 `acpid`：
    
    Bash
    
    ```
    apt update && apt install acpid -y
    ```
    
2. 确保服务已启动：
    
    Bash
    
    ```
    systemctl enable acpid
    systemctl start acpid
    ```
    

---

### 第三步：编写“劫持”脚本 (核心逻辑)

我们要写一个脚本，逻辑是：**“按键了？看看 100 号虚拟机。开着就关掉它，关着就打开它。”**

1. **创建脚本文件：**
    
    Bash
    
    ```
    nano /etc/acpi/powerbtn-pve.sh
    ```
    
2. **粘贴以下代码：**
    
    _(假设你的 Win10 ID 是 100)_
    
    Bash
    
    ```
    #!/bin/bash
    
    VMID=100
    
    # 检查虚拟机状态 (running 或 stopped)
    STATUS=$(qm status $VMID | awk '{print $2}')
    
    if [ "$STATUS" == "running" ]; then
        # 如果正在运行，发送关机指令 (相当于在 Win10 里点关机)
        echo "VM $VMID is running. Shutting down..."
        qm shutdown $VMID
    else
        # 如果是关机状态，发送启动指令
        echo "VM $VMID is stopped. Starting up..."
        qm start $VMID
    fi
    ```
    
3. **保存退出**。
    
4. **赋予执行权限：**
    
    Bash
    
    ```
    chmod +x /etc/acpi/powerbtn-pve.sh
    ```
    

---

### 第四步：把脚本绑定到电源键事件上

现在要告诉 `acpid` 监听器：听到电源键响了，就去跑上面那个脚本。

1. **新建一个事件规则：**
    
    Bash
    
    ```
    nano /etc/acpi/events/powerbtn-pve
    ```
    
2. **粘贴内容：**
    
    Ini, TOML
    
    ```
    event=button/power
    action=/etc/acpi/powerbtn-pve.sh
    ```
    
3. **保存退出**。
    
4. **重启 acpid 服务以生效：**
    
    Bash
    
    ```
    systemctl restart acpid
    ```
    

---

### 第五步：完美体验的最后一块拼图（随 PVE 启动）

现在还有一个逻辑漏洞：**如果整个物理机是断电状态，你按电源键，主板通电，PVE 启动了，但 Win10 不会自动启动。**

你需要设置 Win10 随宿主机启动：

1. 在 PVE 网页 -> **Win10 (100)** -> **Options (选项)**。
    
2. **Start at boot (开机自启):** 勾选。
    
3. **Start/Shutdown order:** 可以设置一个 Order=1，Delay=0。
    

---

### 最终效果验收

现在你的“All-in-One”主机逻辑变成了这样：

1. **完全断电状态下：** 按电源键 -> 主板通电 -> PVE 启动 -> **自动启动 Win10** -> 屏幕亮起进入 Windows。
    
2. **Windows 开机状态下：** 按机箱电源键 -> PVE 收到信号 -> **触发脚本** -> 给 Win10 发送 ACPI 关机指令 -> Windows 正常关机。
    
    - _（此时 PVE 宿主机其实还开着，处于低功耗待机状态）_
        
3. **PVE 待机但 Windows 关机状态下：** 按机箱电源键 -> PVE 收到信号 -> **触发脚本** -> 唤醒 Win10。

- **不建议修改 Reset 键**。

- 保留 Reset 键也有好处：万一你的 Win10 和 PVE 都死机了，你还需要它来强制重启物理机。**
这是一个非常极客但也非常实用的需求！你想让这台机器用起来完全像一台普通的 Windows 电脑：按机箱上的电源键，Windows 关机；再按一下，Windows 开机。

问题解决：
既然手动关机（在 Windows 开始菜单点关机）是完全正常的，那么恭喜你，**你的 Windows 系统、驱动、BIOS 设置全都没问题**。

问题出在**脚本逻辑**和**按键信号的处理**上。

现象分析：你按了一次按钮，Windows 关机了（说明脚本成功执行了第一步）。过了一会儿它又开了，这说明**脚本被触发了第二次**。当第二次触发时，你的虚拟机刚好已经变成了“关机”状态，脚本一看：“哦，现在是关机状态，那我要执行开机命令”，于是又把它开启了。

这通常是因为：

1. **按键信号抖动**：物理开关接触时产生了微小的电火花，被系统识别成了“按下-松开-按下”。
    
2. **ACPI 事件重复**：有些主板按下算一次事件，松开又算一次事件。
    

我们需要把脚本做得“迟钝”一点，给它加一个**超长的冷却时间**。

### 终极修复方案：加装“30秒防误触锁”

我们要修改刚才的脚本，逻辑改成：**“只要我执行过一次操作，接下来的 30 秒内，天王老子按开关我都不理。”**

#### 第一步：修改脚本

在 PVE Shell 中输入：

Bash

```
nano /etc/acpi/powerbtn-pve.sh
```

**清空里面的内容**，复制粘贴下面这个**逻辑增强版**：

Bash

```
#!/bin/bash

# --- 配置区域 ---
VMID=100
LOCKFILE="/tmp/pve_powerbtn_lock"
COOLDOWN=30  # 冷却时间设置为30秒，足够Win10完全关机
# ----------------

# 1. 检查锁文件
if [ -f "$LOCKFILE" ]; then
    # 获取当前时间和文件时间
    NOW=$(date +%s)
    FILE_TIME=$(stat -c %Y "$LOCKFILE")
    DIFF=$(($NOW - $FILE_TIME))

    # 如果距离上次操作不足 30 秒，直接退出，什么都不做
    if [ $DIFF -lt $COOLDOWN ]; then
        echo "操作太频繁（冷却中...），本次忽略。"
        exit 0
    fi
fi

# 2. 更新锁文件时间戳（标记现在开始执行操作）
touch "$LOCKFILE"

# 3. 获取虚拟机状态
# 使用 qm status 获取状态，过滤出 running 或 stopped
STATUS=$(qm status $VMID | awk '{print $2}')

if [ "$STATUS" == "running" ]; then
    # --- 关机逻辑 ---
    echo "虚拟机 $VMID 正在运行，执行关机..."
    # 使用 shutdown 命令（软关机）
    qm shutdown $VMID
    
    # 【关键】再强制更新一次锁，防止关机过程太慢导致误判
    touch "$LOCKFILE"

elif [ "$STATUS" == "stopped" ]; then
    # --- 开机逻辑 ---
    echo "虚拟机 $VMID 已停止，执行开机..."
    qm start $VMID
    
    # 【关键】开机也加锁
    touch "$LOCKFILE"
else
    echo "虚拟机状态未知 ($STATUS)，不做操作。"
fi
```

#### 第二步：保存并测试

1. 按 `Ctrl+O` 回车保存，按 `Ctrl+X` 退出。
    
2. **测试逻辑：**
    
    - 在 Windows **开机** 状态下，按一下机箱电源键。
        
    - 观察屏幕，Windows 应该开始关机。
        
    - **关键点：** 在它关机的过程中，或者刚关机黑屏的时候，**你再去按一下电源键**。
        
    - 如果脚本生效，第二次按键应该**完全没反应**（因为在 30 秒冷却期内）。

### 备选排查：PVE 的 HA（高可用）捣乱？

虽然可能性不大，但如果上面的脚本改了之后，虚拟机依然自动重启，请检查一下你是否不小心开启了 PVE 的 **HA (High Availability)** 功能。

- **什么是 HA：** 它的作用是“只要虚拟机关机了，我就把它拉起来”，保证它永远在线。
    
- **如何检查：**
    
    1. 点击 PVE 网页左侧的 **Datacenter (数据中心)**。
        
    2. 点击中间菜单的 **HA**。
        
    3. 看右边的列表里有没有你的 **Win10 (100)**。
        
    4. **如果有：** 选中它，点击 **Remove (移除)**。
        
    
    - _（家用单机环境千万不要把虚拟机加进 HA，否则你永远关不了机。）_
