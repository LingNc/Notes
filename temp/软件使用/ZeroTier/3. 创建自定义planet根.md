	下载的时候首先确认安装gpg `sudo apt install gpg`
5. 安装ztncui，这是一个用来管理自建网络的网络控制器，包括对网络中设备查看授权等（在作为根服务器的机器上部署最好，不需要修改什么配置）
	1. 参考官网教程 ([ztncui官网](https://key-networks.com/ztncui/))
	2. 我的环境属于（Deb）
	3. curl -O https://s3-us-west-1.amazonaws.com/key-networks/deb/ztncui/1/x86_64/ztncui_0.8.14_amd64.deb （从ztncui官网获取最新版的，参考官网教程，此处是下载安装包）
	4. 安装安装包： `sudo apt install ./ztncui_0.8.14_amd64.deb`
	5. 限制公共网络接口上的 3443 端口（可以自己选择修改http端口）访问权限，仅允许从您的 IP 地址访问（至少在设置管理员密码之前）。
	6. 从已经安装二zerotier-one中获取控制密钥： sudo sh -c "echo ZT_TOKEN=`sudo cat /var/lib/zerotier-one/authtoken.secret` > /opt/key-networks/ztncui/.env"
	7. 设置http端口：sudo sh -c "echo HTTPS_PORT=3443 >> /opt/key-networks/ztncui/.env"
	8. 设置生产环境：sudo sh -c "echo NODE_ENV=production >> /opt/key-networks/ztncui/.env"
	9. 修改权限：sudo chmod 400 /opt/key-networks/ztncui/.env
	10. 修改权限：sudo chown ztncui.ztncui /opt/key-networks/ztncui/.env
	11. 启动服务：sudo systemctl restart ztncui
	12. 在您的网络浏览器中通过 HTTPS 连接到 3443 端口 - 例如 https://my.network.controller:3443
	13. 以用户 **admin** 身份登录，密码为 **password**。

	### 笔记
	- 推荐使用1panel的openresty管理https
	- 默认情况下，ztncui 在本地端口 3000 上监听 HTTP 请求。可以通过 Nginx 进行反向代理（可以将 HTTP 代理为 HTTPS）。也可以按照 README.md 文件中的描述，通过 SSH 连接到 ztncui，该文件位于 [github.com/key-networks/ztncui](https://github.com/key-networks/ztncui)。
	- 请注意，如果在 **.env** 文件中指定了 HTTPS_PORT，ztncui 将在该端口上监听所有网络接口。要限制仅在特定接口上监听，请在 **.env** 文件中添加一行：或为该接口定义的任何 IP 地址或主机名。
	- 更改默认管理员密码的一个好策略是在网络控制器机器上运行一个网络浏览器，并连接到 [http://localhost:3000](http://localhost:3000/) 上的 ztncui，以在启用 HTTPS_PORT 的 HTTPS 之前设置管理员密码。如果网络控制器机器上没有 GUI，您可以使用像 **lynx** 这样的文本网络浏览器。否则，如上述安装说明中所述，如果您想在更改默认管理员密码之前在公共网络接口上启用 HTTPS，强烈建议调整网络控制器机器的防火墙设置，仅允许从您的管理机器连接到 HTTPS_PORT。
	- 您可以通过为自己创建一个管理员用户账户，然后删除默认的管理员账户来提高安全性。
6. 自托管根服务器
	1. 官方提供了两种方式：
		1. 第一种是使用官方的根服务器（planet行星），可以自建moon节点绕行官方根服务器，也就是控制网络连接分发ip等都由根服务器控制，中继流量节点可以通过自定义moon来转发中继流量也可以在已经建立保存链接的两个节点间进行不依赖根服务器进行直接通讯，从而替代部分根服务器功能（在根服务器离线的情况下）。
		2. 通过完全的自托管（self-hosting）根服务器来自主控制整个网络，包括网络创建由自己的控制器控制ip地址分发等，完全独立于官方的根服务器。在更新1.16.0的版本官方在仓库移除了/attic/world的代码，该部分用来生成planet的世界签名，通过修改世界生成代码.cpp文件注释官方的服务器从而自建根服务器。但是可以通过idtool工具进行进行替代原来的操作代码的功能，可以生成世界签名，并且目前官方在移动端提供自定义导入planet文件，并且和之前的代码生成的签名完全兼容，还支持新的QR码导入等，但是在移动端进行moon入轨等功能依然需要zerotier-fix软件实现来完全自托管。
	2. 方法一：使用代码进行构建世界签名 （[源码此处](https://github.com/zerotier/ZeroTierOne/tree/central-controller-1.4.6-202003040912/attic/world)）
		1. 克隆包含world的分支只clone源码：`git clone -b central-controller-1.4.6-202003040912 --depth 1 https://github.com/zerotier/ZeroTierOne.git`
		2. 进入attic/world文件夹，修改mkworld.cpp文件中的
			```cpp
			roots.push_back(World::Root());
			roots.back().identity = Identity("3a46f1bf30:0:76e66fab33e28549a62ee2064d1843273c2c300ba45c3f20bef02dbad225723bb59a9bb4b13535730961aeecf5a163ace477cceb0727025b99ac14a5166a09a3");
		roots.back().stableEndpoints.push_back(InetAddress("185.180.13.82/9993"));
		roots.back().stableEndpoints.push_back(InetAddress("2a02:6ea0:c815::/9993"));
			```
			有这一部分的代码，将官方的根id（自己的使用这个进行查看`cat /var/lib/zerotier-one/identity.public`）和地址替换成自己的，如果没有ipv6就直接删去第二个stableEndpoints即可。
		3. 运行build.sh进行构建mkworld.cpp，构建完成之后会生成一个可执行文件mkworld，运行即可生成一个planet就是包含你的节点的世界签名。该文件就可以在其他电脑或者移动端使用。（参考：[1. Zerotier导入自建planet服务器并使用](1.%20Zerotier导入自建planet服务器并使用.md)）
	3. 方法二：使用zerotier工具进行构建世界签名
		1. 使用某个根服务器zerotier-one平台即可
		2. 依然是首先从各个根服务器获取identity.public配置(linux:`/var/lib/zerotier-one/identity.public`,win:`C:\ProgramData\ZeroTier\One\identity.public`)
		3. 选择一个配置文件进行json的标准化配置文件
			``zerotier-idtool initmoon <identity.public of one root> >>moon.json``
			例如``zerotier-idtool initmoon /var/lib/zerotier-one/identity.public >>moon.json``
		4. 然后使用其他编辑器(vim)打开moon.json
			```json
			{
			"id": "deadbeef00",
			"objtype": "world",
			"roots": [
				{
				"identity": "deadbeef00:0:34031483094...",
				"stableEndpoints": [ "10.0.0.2/9993","2001:abcd:abcd::1/9993" ]
				},
				{
				"identity": "feedbeef11:0:83588158384...",
				"stableEndpoints": [ "10.0.0.3/9993","2001:abcd:abcd::3/9993" ]
				}
			],
			"signingKey": "b324d84cec708d1b51d5ac03e75afba501a12e2124705ec34a614bf8f9b2c800f44d9824ad3ab2e3da1ac52ecb39ac052ce3f54e58d8944b52632eb6d671d0e0",
			"signingKey_SECRET": "ffc5dd0b2baf1c9b220d1c9cb39633f9e2151cf350a6d0e67c913f8952bafaf3671d2226388e1406e7670dc645851bf7d3643da701fd4599fedb9914c3918db3",
			"updatesMustBeSignedBy": "b324d84cec708d1b51d5ac03e75afba501a12e2124705ec34a614bf8f9b2c800f44d9824ad3ab2e3da1ac52ecb39ac052ce3f54e58d8944b52632eb6d671d0e0",
			"worldType": "planet"
			}
			```
		类似上面的，并且将"worldType"修改为planet，并且保证roots里面放的都是PLANET根服务器的节点和对应的公钥文件(identity.public)
	4. 生成带有签名的world文件`zerotier-idtool genmoon moon.json`会生成名为`000000deadbeef00.moon`的文件（以运行这个操作的服务器命名），可以将改文件修改为`planet`或者其他的任意名字，和方法一一样，将其传输到对应设备上并且替换掉对应的planet即可。（[1. Zerotier导入自建planet服务器并使用](1.%20Zerotier导入自建planet服务器并使用.md)）
7. 使用ztncui创建私有的网络，并且其他设备已经添加planet文件，其他设备通过`zerotier-cli join <网络ID>`并且在ztncui控制台进行访问控制后即可正常使用
