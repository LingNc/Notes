1. 网桥（Bridge）是 Linux 中用来连接多个网络接口的虚拟设备，**它本质上是一个软件实现的“交换机”**，可以将物理网卡、虚拟网卡、虚拟机或容器连接在一起，让它们处于同一个局域网中，互相通信。下面用通俗易懂的方式解释它的作用和原理。
	
	---
	
	### **1. 网桥的核心作用**
	网桥就像一个“虚拟的交换机”：
	- **连接多个设备**：将物理网卡（如 `eth0`）、虚拟机网卡、容器虚拟网卡等连接在一起。
	- **统一管理网络**：所有连接到网桥的设备共享同一个网络配置（IP 段、网关等）。
	- **隔离或扩展网络**：可以创建多个网桥，实现不同网络之间的隔离（类似 VLAN）。
	
	---
	
	### **2. 网桥的典型场景**
	#### **场景 1：虚拟机联网**
	- **问题**：你有一台物理服务器，运行了 KVM 虚拟机，想让虚拟机和宿主机（物理机）处于同一局域网，并访问外网。
	- **解决方案**：
	  1. 创建一个网桥（如 `br0`），将物理网卡 `eth0` 加入网桥。
	  2. 虚拟机的虚拟网卡也连接到 `br0`。
	  3. 此时，虚拟机会通过 `br0` 获取和物理机同一网段的 IP，就像插入了同一台物理交换机。
	
	#### **场景 2：容器通信**
	- **问题**：你在 Docker 中运行了多个容器，希望它们能互相直接通信，而不是通过 NAT。
	- **解决方案**：
	  1. Docker 默认会创建一个网桥 `docker0`，所有容器连接到 `docker0`。
	  2. 容器之间通过 `docker0` 直接通信，无需经过宿主机的 NAT。
	
	#### **场景 3：内部隔离网络**
	- **问题**：你想创建一个完全隔离的私有网络，仅供虚拟机或容器之间通信（不连接外网）。
	- **解决方案**：
	  1. 创建一个网桥（如 `br-internal`），但不绑定物理网卡。
	  2. 虚拟机和容器连接到 `br-internal`，它们的 IP 由你手动分配，无法访问外部网络。
	
	---
	
	### **3. 网桥的工作原理**
	- **交换机行为**：网桥会学习连接到它的设备的 MAC 地址，并根据 MAC 地址表转发数据包。
	- **透明连接**：连接到网桥的设备感知不到网桥的存在，就像直接插入了物理交换机。
	- **IP 配置**：网桥本身可以配置 IP（用于宿主机通信），但虚拟机/容器不依赖网桥的 IP。
	
	---
	
	### **4. 网桥 vs 物理交换机 vs 路由器**

	| **设备**   | **作用**                         |
	| -------- | ------------------------------ |
	| 物理交换机    | 硬件设备，连接多台物理设备，根据 MAC 地址转发数据。   |
	| Linux 网桥 | 软件实现的交换机，连接物理/虚拟设备，功能类似物理交换机。  |
	| 路由器      | 连接不同网络（如局域网和互联网），基于 IP 地址转发数据。 |
	
	---
	
	### **5. 网桥配置的核心步骤**
	以连接虚拟机为例：
	1. **创建网桥**：
	   ```bash
	   sudo ip link add br0 type bridge
	   sudo ip link set br0 up
	   ```
	2. **绑定物理网卡**（让网桥接管物理网络）：
	   ```bash
	   sudo ip link set eth0 master br0    # 将 eth0 加入网桥
	   sudo ip addr flush dev eth0         # 清除 eth0 的 IP
	   sudo ip addr add 10.85.11.100/25 dev br0  # 为网桥分配 IP
	   ```
	3. **连接虚拟机**：
	   - 在 KVM/QEMU 中指定虚拟机的网卡连接到 `br0`。
	   - 虚拟机会通过 DHCP 或手动配置，获取与宿主机同一网段的 IP。
	
	---
	
	### **6. 常见问题解答**
	#### **Q1：为什么网桥要绑定物理网卡？**
	- **目的**：为了让虚拟机/容器通过物理网卡访问外部网络。
	- **原理**：物理网卡成为网桥的“出口”，所有流量通过它转发到外部网络。
	
	#### **Q2：网桥和路由有什么区别？**
	- **网桥**：工作在数据链路层（MAC 地址），连接同一局域网的设备。
	- **路由**：工作在网络层（IP 地址），连接不同网络（如局域网和互联网）。
	
	#### **Q3：如何查看网桥的状态？**
	```bash
	bridge link     # 查看网桥绑定的接口
	ip addr show br0 # 查看网桥的 IP 配置
	```
	
2. 以下是使用 `nmcli` 配置网桥并设置静态 IP（如 `10.85.11.x` 网段）的完整步骤，适用于企业或实验室网络环境。假设你的物理网卡已连接到外网（如交换机/路由器分配的 `10.85.11.x` 网段）。
	### **场景描述**
	- **物理网卡**：`eth0`（连接到外网，假设外网网关为 `10.85.11.1`）。
	- **网桥名称**：`br0`（用于连接虚拟机/容器）。
	- **目标**：让网桥 `br0` 拥有静态 IP（如 `10.85.11.100/25），并允许虚拟机通过该网桥访问外网。
	
	---
	
	### **步骤 1：创建网桥并绑定物理网卡**
	#### **1.1 创建网桥 `br0`，设置静态 IP**
	```bash
	# 创建网桥，指定 IP 和子网掩码
	sudo nmcli con add type bridge con-name br0 ifname br0 \
	    ipv4.addresses 10.85.11.100/25 \
	    ipv4.gateway 10.85.11.1 \
	    ipv4.dns "59.70.159.10" \
	    ipv4.method manual
	```
	- **关键参数**：
	  - `ipv4.addresses 10.85.11.100/25`：网桥的静态 IP 和子网掩码。
	  - `ipv4.gateway 10.85.11.1`：外网网关（需替换为你的实际网关）。
	  - `ipv4.dns`：DNS 服务器地址（可替换为企业内部 DNS）。
	
	#### **1.2 将物理网卡 `eth0` 加入网桥**
	```bash
	# 绑定物理网卡到网桥（作为从属接口）
	sudo nmcli con add type bridge-slave con-name br0-eno1 ifname eno1 master br0
	```
	
	#### **1.3 激活配置**
	```bash
	# 启动网桥和从属接口
	sudo nmcli con up br0
	sudo nmcli con up br0-eno1
	
	# 禁用原物理网卡的独立连接（避免冲突）
	sudo nmcli con down eno1
	```
	
	---
	
	### **步骤 2：验证配置**
	#### **2.1 检查网桥 IP 和状态**
	```bash
	# 查看网桥 IP
	ip addr show br0
	
	# 预期输出：
	# inet 10.85.11.100/25 brd 10.85.11.127 scope global br0
	```
	
	#### **2.2 测试外网连通性**
	```bash
	# 通过网桥 ping 网关
	ping -I br0 10.85.11.1
	
	# 测试 DNS 解析
	nslookup google.com 8.8.8.8
	```
	
	#### **2.3 查看网桥绑定的接口**
	```bash
	# 确认 eth0 已加入网桥
	nmcli con show br0 | grep bridge-slave
	```
	
	---
	
	### **步骤 3：连接虚拟机/容器到网桥**
	#### **3.1 KVM/QEMU 虚拟机**
	启动虚拟机时指定网桥：
	```bash
	virt-install --network bridge=br0 ...
	```
	
	#### **3.2 Docker 容器**
	启动容器并使用网桥：
	```bash
	docker run --network=bridge -it alpine
	```
	
	---
	
	### **故障排除**
	#### **问题 1：网桥无法 ping 通网关**
	- **可能原因**：
	  - 物理网卡 `eth0` 未正确加入网桥。
	  - 网关地址配置错误。
	- **解决**：
	  ```bash
	  # 检查物理网卡是否在网桥中
	  bridge link show
	
	  # 重新绑定物理网卡
	  sudo nmcli con del br0-eno1
	  sudo nmcli con add type bridge-slave con-name br0-eno1 ifname eno1 master br0
	  sudo nmcli con up br0-eno1
	  ```
	
	#### **问题 2：虚拟机无法获取 IP**
	- **可能原因**：
	  - 网桥未启用 DHCP 中继（若外网需要 DHCP）。
	  - 防火墙阻止流量。
	- **解决**：
	  ```bash
	  # 允许网桥流量转发
	  sudo firewall-cmd --add-interface=br0 --zone=trusted --permanent
	  sudo firewall-cmd --reload
	  ```
