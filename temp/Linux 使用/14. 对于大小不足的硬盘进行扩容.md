5. 具体操作：
	1. 在 Hyper-V 管理器中操作 (虚拟机需关机)
		1. **关闭 Linux 虚拟机**
		    - 在 Hyper-V 管理器中，右键点击你的 Linux 虚拟机，选择“关闭”。**不要**选择“关闭状态”，要确保操作系统完全关闭。
		2. **扩容主硬盘 (从 10GB 扩容)**
		    - 在 Hyper-V 管理器中，右键点击你的虚拟机，选择“设置”
		    - 在左侧导航栏中，找到你的主硬盘。它通常位于“SCSI 控制器”或“IDE 控制器”下，名为 `你的虚拟机名.vhdx`。
		    - 选中该硬盘，在右侧点击“编辑”按钮。
		    - 在“编辑虚拟硬盘向导”中，选择“扩展”。
		    - 输入你希望扩容到的**新总大小**。例如，如果你想增加 10GB，就输入 `20` GB。
		    - 完成向导。此时，你的主虚拟硬盘的总容量已经变大了，但 Linux 系统内部还不知道。
		3. **添加新的 4GB 硬盘用于 Swap**
		    - 同样在虚拟机的“设置”中，选中“SCSI 控制器”。
		    - 在右侧选择“硬盘驱动器”，然后点击“添加”。
		    - 选择“新建”来创建一个新的虚拟硬盘。
		    - 在“新建虚拟硬盘向导”中：
		        - **选择磁盘格式**：推荐 VHDX。
		        - **选择磁盘类型**：推荐“动态扩展”，它不会立即占用 4GB 物理空间。
		        - **指定名称和位置**：给它一个清晰的名字，例如 `Linux-Swap.vhdx`。
		        - **配置磁盘**：设置大小为 `4` GB。
		    - 完成向导。现在你的虚拟机已经连接了两个虚拟硬盘：一个扩容后的主硬盘和一个新的 4GB 硬盘。
		4. **启动虚拟机**
		    - 现在可以启动你的 Linux 虚拟机了。
	2. 在 Linux 客户机中配置新硬盘和扩容**
		接下来的所有操作都在 Linux 虚拟机的终端中完成。你需要使用 `sudo` 或者切换到 `root` 用户
		1. 识别磁盘
		首先，我们需要查看系统中的磁盘和分区情况。
		
		```
		lsblk
		```
		你应该会看到类似下面的输出：
		```
        NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
        sda      8:0    0   20G  0 disk 
        ├─sda1   8:1    0  476M  0 part /boot/efi
        ├─sda2   8:2    0  8.4G  0 part /
        └─sda3   8:3    0  1.2G  0 part [SWAP]
        sr0     11:0    1 1024M  0 rom  
		```
		- `sda` 是你的主硬盘，现在大小应该是 `20G`。
		- `sda1` 是你的根分区 `/`。
		- `sda2` 是你**旧的** swap 分区。
		好的，这是一个非常经典且常见的Linux服务器运维操作。你将虚拟机（或物理机）的硬盘从10G扩容到了20G，现在需要让操作系统识别并使用这些新增的空间，同时按照你的要求调整分区。

我们来一步一步地、安全地完成这个任务。
**在开始之前，请务必阅读：**

> **警告：** 分区操作具有风险性，错误的操作可能导致数据丢失或系统无法启动。强烈建议在执行此操作前**备份重要数据**。
### 2\. 整体操作思路

你的目标是将 `sda3` (SWAP) 和新增加的10G空间合并到 `sda2` (根分区 `/`) 中。

整个过程分为三个主要阶段：

1.  **停用并删除SWAP分区 (`sda3`)**
2.  **扩展根分区 (`sda2`)** 来利用所有可用空间
3.  **创建并启用SWAP文件**

下面是详细的命令行操作步骤。

-----

### 步骤一：停用并删除SWAP分区

#### 1\. 停用SWAP分区

首先，我们需要让系统停止使用 `/dev/sda3` 作为交换空间。

```bash
sudo swapoff /dev/sda3
```

你可以使用 `free -h` 或 `swapon --show` 命令来确认SWAP是否已关闭。执行后应该看不到任何输出。

#### 2\. 修改 fstab 文件

为了防止系统下次启动时还尝试挂载这个已经不存在的SWAP分区而导致启动失败，需要从 `/etc/fstab` 文件中移除或注释掉相关条目。

```bash
sudo nano /etc/fstab
```

在文件中找到类似下面这一行（UUID可能不同）：

```
# <file system> <mount point>   <type>  <options>       <dump>  <pass>
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx none            swap    sw              0       0
```

或者可能是：

```
/dev/sda3    none    swap    sw    0    0
```

在这行前面加上一个 `#` 号，将其注释掉：

```
# UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx none            swap    sw              0       0
```

保存并退出编辑器 (在 `nano` 中是 `Ctrl+X`，然后按 `Y`，再按 `Enter`)。

#### 3\. 删除分区表中的 sda3

现在我们使用分区工具来删除 `sda3`。这里我们使用 `fdisk`，这是一个强大且常用的工具。

```bash
sudo fdisk /dev/sda
```

进入 `fdisk` 的交互式命令行后，按顺序输入以下指令：

1.  输入 `p` 然后按 `Enter`。这会打印出当前的分区表，让你最后确认一下 `sda3` 的信息。
2.  输入 `d` 然后按 `Enter`。`fdisk` 会询问你要删除哪个分区。
3.  输入 `3` 然后按 `Enter`，选择删除第3个分区 (`sda3`)。
4.  输入 `w` 然后按 `Enter`。这将把更改写入分区表并退出。**这一步是真正执行删除操作，请谨慎。**

此时，`sda3` 分区已经被删除了。你可以再次运行 `sudo lsblk` 查看，应该已经看不到 `sda3` 了。

-----

### 步骤二：扩展根分区 (`sda2`)

这是最关键的一步。我们的策略是：**删除 `sda2` 的分区记录，然后用相同的起始位置和新的结束位置（硬盘末尾）重新创建它**。

> **请放心：** 这个操作只是修改分区表中的元数据，并不会删除 `sda2` 上的实际文件数据。但前提是，**你必须确保新建分区的起始扇区（Start Sector）与原来完全一致！**

继续在终端中操作：

```bash
sudo fdisk /dev/sda
```

1.  输入 `p` 并按 `Enter`。打印分区表。**找到 `sda2` 对应的 "Start" 值，并把它记下来！** 这个数字至关重要。假设这个值是 `2050048`。

2.  输入 `d` 并按 `Enter`。

3.  输入 `2` 并按 `Enter`，选择删除 `sda2`。

4.  现在我们重新创建它：

      * 输入 `n` 并按 `Enter` (n代表new，新建分区)。
      * `fdisk` 会问你分区类型，输入 `p` (p代表primary，主分区)，按 `Enter`。
      * 它会问你分区号，输入 `2`，按 `Enter`。
      * **关键一步**：它会问你 `First sector`，**输入你刚才记下的 `sda2` 的起始扇区号** (例如 `2050048`)，然后按 `Enter`。
      * 对于 `Last sector`，直接按 `Enter` 接受默认值即可。这会自动将分区的末尾扩展到磁盘的最后。
      * `fdisk` 可能会提示 `Partition #2 contains a ext4 signature.` 并询问是否移除。**回答 `N` (No)**，千万不要移除签名！

5.  最后，输入 `w` 并按 `Enter`，保存更改并退出。

#### 扩展文件系统

此时，分区的大小已经改变，但文件系统仍然是旧的大小。我们需要让文件系统“填满”整个新分区。

因为我们操作的是根分区，系统可能需要重启来识别新的分区表。**请先重启你的Debian系统**。

```bash
sudo reboot
```

重启后，登录系统，执行以下命令来扩展 `ext4` 文件系统：

```bash
sudo resize2fs /dev/sda2
```

这个过程会自动完成，通常很快。

#### 验证结果

现在，你可以用 `df -h` 命令来查看根分区 `/` 的大小。

```bash
df -h /
```

你应该能看到 `/` 的大小已经接近 19G 了，这证明分区和文件系统都已成功扩展。`lsblk` 的输出应该类似这样：

```
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   20G  0 disk
├─sda1   8:1    0  476M  0 part /boot/efi
└─sda2   8:2    0 19.5G  0 part /
sr0     11:0    1 1024M  0 rom
```

-----

### 步骤三：创建并启用SWAP文件

现在你的系统没有交换空间了，我们来创建一个swap文件作为替代。

#### 1\. 创建Swap文件

我们将创建一个2G大小的swap文件（大小可以根据你的需求调整）。

```bash
# 使用 fallocate 命令快速创建一个2G的文件
sudo fallocate -l 2G /swapfile
```

#### 2\. 设置正确的权限

为了安全，swap文件只能被root用户读写。

```bash
sudo chmod 600 /swapfile
```

#### 3\. 将文件格式化为Swap

```bash
sudo mkswap /swapfile
```

#### 4\. 启用Swap文件

```bash
sudo swapon /swapfile
```

#### 5\. 设置开机自动挂载

为了让系统重启后自动启用这个swap文件，需要再次编辑 `/etc/fstab` 文件。

```bash
sudo nano /etc/fstab
```

在文件末尾添加新的一行：

```
/swapfile    none    swap    sw    0    0
```

保存并退出编辑器。

#### 6\. 最终验证

检查一下swap是否已经成功启用。

```bash
swapon --show
```

你应该会看到类似输出：

```
NAME       TYPE SIZE USED PRIO
/swapfile  file   2G   0B   -2
```

或者使用 `free -h`：

```bash
free -h
```

你会看到 "Swap" 一行有了 2.0G 的总空间。

至此，你已成功将硬盘扩容后的空间分配给了根目录，删除了旧的SWAP分区，并用一个更灵活的SWAP文件替代了它。
