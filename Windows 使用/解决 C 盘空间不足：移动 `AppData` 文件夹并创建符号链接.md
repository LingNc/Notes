## 问题

在 Windows 系统中，`AppData` 文件夹通常位于 `C:\Users\YourUserName\AppData`，存储了许多应用程序的配置和数据文件。随着使用时间的增加，`AppData` 文件夹可能会占用大量空间，导致系统盘（通常是 C 盘）空间不足。

## 思考方案

为了释放系统盘空间，可以将 `AppData` 文件夹移动到其他磁盘（如 D 盘），并通过创建符号链接的方式，使系统和应用程序仍然可以正常访问 `AppData` 文件夹的内容。具体方案如下：
1. 使用 `robocopy` 命令无损复制 `AppData` 文件夹到新位置。
2. 使用 `mklink` 命令创建符号链接，将原始路径指向新位置。
3. 验证符号链接是否正常工作，并清理旧文件夹。

> [!IMPORTANT]
> 1. 在进行任何操作之前，建议备份重要数据，以防意外。
> 2. 确保以管理员身份运行命令提示符，否则可能无法创建符号链接或复制文件。
> 3. 某些应用程序可能依赖于 `AppData` 文件夹的原始路径，移动后可能导致部分功能异常。（目前未发现）

## 方法实现

### 选择进行操作的环境

要复制`AppData`要保证被复制的用户没有在使用，没有程序正在使用`AppData` 文件夹中的文件。
环境编号：（后面使用`环境x`表示第几个环境）
1. 使用 `Administrator` 用户登录 Windows 系统进行操作。
2. 进入恢复选项的命令提示符操作。
   - 开机情况下点击"更新和安全" => "恢复" => "高级启动"，重启后点击"高级选项"，然后选择"命令提示符"。
3. 使用`PE`微系统（如 Windows PE）进行操作。
   - `PE`中自带的`cmd`没有`robocopy`命令，可以使用`C:\Windows\System32`下的`cmd.exe`作为命令提示符

### 使用 `robocopy` 无损复制文件

`robocopy` 是 Windows 自带的强大文件复制工具，支持无损复制文件并避免递归问题。

1. **以管理员身份打开命令提示符**：
   - 按 `Win + X`，选择“命令提示符（管理员）”或“Windows PowerShell（管理员）”。

2. **使用 `robocopy` 复制 `AppData` 文件夹**：
   - 假设将 `AppData` 从 `C:\Users\YourUserName\AppData` 复制到 `D:\AppData`，运行以下命令：
      ```cmd
      robocopy "C:\Users\YourUserName\AppData" "D:\AppData" /E /COPYALL /XJ
      ```
      > 参数说明：
      > - `/E`：复制所有子目录，包括空目录。
      > - `/COPYALL`：复制所有文件属性（包括权限、时间戳等）。
      > - `/XJ`：排除交接点（避免递归问题）。
    - **可能的问题**：可能有部分文件拒绝访问（错误5），因为当前系统正在运行中，可能有一些服务等正在使用该文件。这个时候只能使用环境2恢复模式来进行操作。

   - *在**环境2**恢复模式的`cmd`中，盘符并不是系统中的盘符，可能需要使用`diskpart`命令查看当前的盘符。
     1. 输入 `diskpart` 进入磁盘分区工具。
     2. 输入 `list volume` 查看所有分区的盘符。
     3. 找到目标盘符（如 D 盘），然后使用 `exit` 退出 `diskpart`。
     4. 注意修改命令，复制到正确的位置。
     > 可能的问题：
     > - 在`AppData\Local\Temp`文件夹中可能依然有部分形如`0*.tmp`的文件无法复制（错误：1920），但是该Temp文件夹内容是可以忽略的，可以通过添加一个排除参数来不复制`Temp`之后再处理。
     > - 使用`/xd path`来选择要排除的文件夹路径
     > - 或者尝试使用*傲梅分区*助手来进行复制和*PE系统*。

3. **重命名原始文件夹**：
   - ***环境2**，由于在命令行操作，重命名前需要去除`AppData`的隐藏属性
     ```cmd
     attrib -h -s "C:\Users\YourUserName\AppData"
     ```
      > 参数说明：
      > - `-h`：去除隐藏属性。
      > - `-s`：去除系统属性。
   - ***环境2**将原始 `AppData` 文件夹重命名，（在命令行）使用 `ren` 或者 `rename` 命令：
     ```cmd
     ren "C:\Users\YourUserName\AppData" "AppData_Old"
     ```
     注意使用的时候被重命名对象请使用绝对路径，或者重命名当前目录下的文件夹。
   - **非命令行**可选择在资源管理器重命名

### 使用 `mklink` 创建符号链接

通过 `mklink` 命令创建符号链接，使系统仍然可以访问移动后的 `AppData` 文件夹。

1. **创建符号链接**：
   - 运行以下命令，将 `AppData` 文件夹的路径指向新的位置：
     ```cmd
     mklink /J "C:\Users\YourUserName\AppData" "D:\AppData"
     ```
    > 参数说明：
    > - `/J`：创建目录联接（Junction），适用于文件夹。不能跨不同的磁盘系统（分区），可以跨同一个分区内的盘符。
   - 应该也可以使用符号链接，注意不要使用相对路径
       ```cmd
       mklink /D "C:\Users\YourUserName\AppData" "D:\AppData"
       ```
      > 参数说明：
      > - `/D`：创建符号链接（Symbolic Link），可以跨分区。
   - ***环境2**
      由于在命令提示符中并且这个盘符不正确，有两种方法
      1. 直接链接盘符下的地址，需要记住目标的盘符
         - 命令和上面一样
      2. 使用 `volumeID`
         - 首先获取所有盘符的卷标：
            ```cmd
            :: 获取所有卷标
            mountvol
            :: 获取指定卷标
            vol D:
            ```
         - 然后使用卷标创建链接：
           ```cmd
           mklink /D "C:\Users\YourUserName\AppData" "\\?\Volume{卷标}\AppData"
           ```

2. **验证符号链接**：
   - 打开 `C:\Users\YourUserName\AppData`，确认它指向 `D:\AppData` 的内容。
   - ***环境2**，可以使用 `dir` 命令查看链接是否正确：
     ```cmd
     dir "C:\Users\YourUserName"
     ```
     ![](7375C9855D99304608A1F36216201BC9.jpg)
		但是如果使用方法1则无法进入 `AppData` 文件夹验证。

### 删除旧文件夹

进入系统使用一段时间后，如果确认新位置的文件和符号链接正常工作，可以删除旧文件夹。

1. **删除旧文件夹**：
   - 运行以下命令：
     ```cmd
     rmdir /s /q "C:\Users\YourUserName\AppData_Old"
     ```

## 异常

1. **`0x00000005` 拒绝访问**
	![](拒绝访问.png)
	可能是因为没有管理员权限或者被复制的文件正在被使用。
   > **解决：**
   > 确保是在上面所说的三种环境中，如果**环境1**无法使用，请考虑**环境2**或者**环境3**。

2. **环境2** **空间不足**
	![](空间不足.png)
   可能是在**环境2**中由于磁盘盘符发生改变，复制到了不该复制到的位置，比如我要复制到`D盘`但是发现`D盘`变成了`G盘`
	![](7D6FD9EB4108C54DAC2C0679A3BB7224.jpg)
   > **解决：**
   > 1. 重新使用`diskpart`命令查看当前的盘符，确认目标盘符。
   > 2. 修改命令中的目标盘符，重新执行复制命令。
3. 1920 正在更改属性
	这个文件一般在 `Local\Temp` 中，这个文件夹可以排除掉，通过 `/xd` 选项。
4. 右键win标，点击终端出现无法使用
